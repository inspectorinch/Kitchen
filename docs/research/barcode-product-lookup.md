# Barcode product lookup (checked 2026-11-25)

## Pick: Open Food Facts (OFF) behind `src/platform/barcode` + a backend proxy
- **License:** database under ODbL (attribution + share-alike), individual contents (photos, text) under the Database Contents License. Share-alike applies if we combine OFF data with other databases into a derived database: **do not merge OFF rows into other product sources or store them as a mixed catalogue**; lookup-and-display with attribution, plus caching our own per-kitchen item, is the safe pattern (OFF's own caching tutorial says caching is still bound by ODbL and not to mix with external product data). Sources: openfoodfacts.github.io/openfoodfacts-server/api; .../tutorials/license-be-on-the-legal-side; support.openfoodfacts.org article "Are there conditions to use the API?".
- **Cost / auth:** free, no API key for reads.
- **Rate limits (per IP):** 15 requests/min for product reads, 10/min for search; exceeding can get the IP banned; global limits return HTTP 503. If requests come directly from users' phones the limit applies per user. So **call it from the app (per-user IP), not from one Cloud Function IP**, or cache. Must send a custom User-Agent like `Kitchen/1.0 (contact)`. Don't use search for search-as-you-type. (same API page, read 2026-11-25)
- **Endpoint:** `GET https://world.openfoodfacts.org/api/v2/product/<barcode>.json?fields=code,product_name,brands,quantity,categories_tags,image_front_small_url` (fields param documented in the API cheat sheet). Response: `status` 1 found, 0 not found, then `product`. Bulk: `/api/v2/search?code=a,b,c&fields=...`. A v3.6 product endpoint exists; the schema changed on 2026-05-27 (product version 1004: `*_hierarchy` and `*_lc` fields removed, `*_tags` now canonical, new `tags_sources`) so pin `fields` and tolerate missing ones. Normalise barcodes (UPC-A 12 digits to EAN-13 with leading 0) and validate the check digit before calling (OFF scanning tutorial).
- **Fields we need:** `code`, `product_name`, `brands`, `quantity`, `categories_tags` (feeds auto-sort into fridge/pantry), `image_front_url`. Nutrition (`nutriments`, Nutri-Score) is out of scope (2.0).
- **US coverage:** the US is the largest country on OFF (about 860k products listed, countries page); OFF's own dashboard says some 640,000 products are reported sold in the US (2024 dashboard); a third-party app maker estimated around 595k US branded items in 2023 against about 3M active US branded products (MacroFactor post, Reddit, weak source). Treat as **good but not complete: expect misses on store brands and new items**. Data is crowd-sourced, any field can be missing.
- **Miss handling (required):** if `status: 0` or no `product_name`, fall through to manual entry with the scanned barcode saved on the item; optional later: let the user contribute (needs OFF account; not now).

## Alternatives (not verified in depth; not chosen)
- USDA FoodData Central "Branded Foods": free US government data, public domain, has GTIN/UPC; API key is free but the OFF wiki notes the USDA branded set was already imported into OFF once. Good second source for US misses (no ODbL conflict, but then mixing rules for OFF still apply to OFF rows). Check current rate limits on fdc.nal.usda.gov before relying on it.
- UPCitemdb and similar: paid/limited free tiers, terms not checked. Skip unless OFF misses are too frequent in the owner's real pantry photos.

## Plan impact
Ship OFF with a USDA fallback behind the same adapter interface (`lookup(barcode) -> {name, brand, size, category, imageUrl} | null`); stand-in is the fixed product table. Add OFF attribution text on the add-by-barcode screen and in Settings > About.
